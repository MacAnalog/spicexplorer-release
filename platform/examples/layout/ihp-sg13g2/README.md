# IHP sg13g2 layout generation (prototype)

Programmatic **layout generation + physical signoff + parasitic extraction** for IHP
`sg13g2`, driven from Python. Prototype stage (scripts + a notebook); the reusable parts
now live in the platform packages **`spicexplorer-signoff`** (DRC/LVS/PEX runners with
structured verdicts, `run_flow`, post-layout splice, sensitivity injection) and
**`spicexplorer-layout`** (generator contract, `GdsBuilder`, patterns) — `gen_5t_ota_gf.py`
follows that contract (`build(params, sizing=None)`, `CELL`, `BOUNDS`) and is the reference
generator; `run_flow(GdsBuilder(...), {})` reproduces this dir's DRC 0 / LVS match / kpex-CC
result end-to-end. Worked example: a rough **5T OTA** (`amp_001_5t` from the `analog-db` submodule),
generated by **two independent lanes** that both pass full signoff:

| Lane | Dir | Generator | Placement |
|---|---|---|---|
| **PyCell** | [`5t_ota/`](5t_ota/) | foundry PyCells via the klayout module | hardcoded single row |
| **gdsfactory** | [`5t_ota_gf/`](5t_ota_gf/) | `gdsfactory` + [`ihp-gdsfactory`](https://github.com/gdsfactory/ihp) | computed rows + mirrored pairs |

Both then flow into the same engine-agnostic **signoff** (KLayout DRC/LVS + Magic/netgen)
and **PEX** ([`pex_kpex.py`](pex_kpex.py), klayout-pex) + **pre/post-layout simulation**
([`sim_pex_compare.py`](sim_pex_compare.py), ngspice). The gdsfactory lane's compact,
symmetric floorplan cuts the post-layout UGF penalty from **−4.45 MHz to −0.72 MHz**, and
its parameterized placement is **optimized in-loop** against DRC/LVS/PEX/sim
([`5t_ota_gf/optimize_layout.py`](5t_ota_gf/optimize_layout.py)): 232.1 → **205.9 µm²**
(−11.3%) with the error term also improved — see
[`5t_ota_gf/README.md`](5t_ota_gf/README.md) for the full comparison.

## Why this works here

The IHP foundry PyCells (`sg13g2_pycell_lib`: `nmos`, `pmos`, `cmim`, `npn13G2`, `rsil`,
inductors, RF devices, taps, `via_stack`, …) use `from __future__ import annotations`, which
KLayout's *embedded* CPython 3.6 rejects. Driven from an **external Python 3.11** with the
pip `klayout` module they import and instantiate fine — so we generate layout in Python and
never touch the KLayout GUI interpreter.

DRC/LVS run through the PDK's own Ruby decks via a working `klayout` executable. On the
research server that's the no-root `~/local/klayout-runtime` shim; see the workspace memory
note *KLayout+IHP layout env* / `~/local/klayout-runtime/SETUP.md`.

## Two signoff flows (both pass)

The 5T OTA passes signoff on **both** tool chains, which cross-check each other:

| Check | KLayout (`signoff.py`) | IIC-OSIC / Magic+netgen (`signoff_magic_netgen.py`) |
|---|---|---|
| **DRC** | 0 violations (`--no_density`) | Magic DRC = 0 |
| **LVS** | "Netlists match" | netgen "Circuits match uniquely" |

KLayout runs DRC **and** LVS in one engine. The Magic+netgen chain is the classic
efabless/sky130/CACE flow: **Magic** for DRC, **netgen** for the netlist comparison. On this
server magic is conda-forge `magic` 8.3.486 and netgen is a from-source build of 1.5.99
(both wrapped on `PATH`).

> **Known gap — magic-native extraction.** Magic *DRC* works on the KLayout-generated GDS,
> but magic's *device extraction* does not yet recognise the KLayout-PyCell geometry (its
> `.ext` shows POLY/DIFF nodes but no `fet` — a layer/implant-recognition mismatch). So the
> netgen LVS is fed the **KLayout-extracted** layout netlist (correct) rather than a
> magic-extracted one. netgen is the comparator either way; wiring magic-native extraction
> (layer-recognition tuning, or generating the layout from magic pcells) is a follow-up.

## Parasitic extraction (PEX) — klayout-pex

Open-source PEX for sg13g2 works via **[klayout-pex](https://github.com/iic-jku/klayout-pex)**
(`kpex`), the KLayout-integrated extractor with first-class IHP support (the PDK even ships
the process stack as `libs.tech/parasitics/itf/sg13g2_typ.itf`). It runs KLayout LVS
internally for connectivity, then extracts coupling/ground **C** and wire **R** (modes
`CC`/`RC`/`R`; engines: built-in 2.5D — used here — plus optional FasterCap/magic).

```bash
conda activate pex                     # py3.12 env (kpex needs >= 3.12)
python pex_kpex.py --gds 5t_ota_gf/ota_5t_gf.gds --cell ota_5t_gf \
    --schematic 5t_ota_gf/ota_5t_gf_lvs.spice          # -> *_k25d_pex_netlist.spice
conda activate ai_env
python sim_pex_compare.py --schematic 5t_ota_gf/ota_5t_gf_lvs.spice \
    --pex 5t_ota_gf/pex_out/kpex/ota_5t_gf__ota_5t_gf/ota_5t_gf_k25d_pex_netlist.spice \
    --cell ota_5t_gf                                   # pre vs post-layout dcgain/UGF/PM
```

The PEX netlist keeps the six `sg13_lv_*` devices (with layout-accurate `AS/AD/PS/PD`) and
adds the parasitic network; `sim_pex_compare.py` rewrites `M` cards to `X` cards (ngspice's
sg13 devices are subcircuits) and runs the amp_001_5t `ac_open_loop` bench on both.

PEX notes / gotchas:

- kpex drives the **KLayout executable's** Ruby LVS engine, and its deck needs **Ruby ≥ 2.6**
  — the rpm-shim batch klayout (Ruby 2.5) fails with a syntax error. Point
  `KPEX_KLAYOUT_EXE` at the py3.11 source build's batch wrapper
  (`~/local/klayout-py311/klayout-batch.sh`, Ruby 2.7); `pex_kpex.py` defaults to it.
- **Magic-native RC extraction stays a dead end** here: magic reads the GDS (DRC works)
  but extracts no `fet` devices from either lane's geometry, and the PDK's
  `ihp-sg13g2-extract.tech` has no `cifinput` section (it's for magic-native databases).
  kpex sidesteps magic entirely.
- FasterCap (3D field-solver accuracy) is a drop-in upgrade later: install FasterCap,
  swap `--2.5D` for `--fastercap`.

## Run it

```bash
cd 5t_ota
python gen_5t_ota.py            # -> ota_5t.gds
python signoff.py              # KLayout DRC (--no_density) + LVS  -> both PASS
python signoff_magic_netgen.py # Magic DRC + netgen LVS (IIC-OSIC style)  -> both PASS
./open_in_klayout.sh           # open ota_5t.gds in the KLayout GUI to tweak by hand
```

### Tweak it in the KLayout GUI (with live PyCells)

`ota_5t.gds` opens directly in KLayout — it *is* the editable layout file — and it retains
**live PyCell instances**: select an `nmos`/`pmos`/`via_stack` and edit its `w`/`l`/`ng` in the
PCell parameter dialog. Run `./open_in_klayout.sh` on a machine with an X display; it opens
edit mode with the IHP `sg13g2.lyp` colors and the `SG13_dev` PyCell library loaded. See
[`KLAYOUT_CHEATSHEET.md`](KLAYOUT_CHEATSHEET.md) for the shortcuts and the exact edit workflow.

The catch: the IHP PyCells need Python ≥3.11 (`StrEnum`, `from __future__ import annotations`)
but the stock portable KLayout embeds Python 3.6, so its GUI can't run them. On srv-elamien
this is solved by a KLayout built from source against Python 3.11 at `~/local/klayout-py311`
(see its `SETUP.md`); `open_in_klayout.sh` uses it automatically. If that build is absent, the
launcher falls back to plain `klayout -rx` — baked geometry only, PyCells disabled.

After edits, re-run `signoff.py` / `signoff_magic_netgen.py` to re-check DRC/LVS. (If you copy
the GDS to another machine's KLayout, install the IHP KLayout PyCell libs there for live PCells,
or just load `sg13g2.lyp` for colors and edit the baked geometry.)

Or work through [`5t_ota/5t_ota_layout.ipynb`](5t_ota/5t_ota_layout.ipynb), which builds the
layout, renders a PNG, and runs signoff inline.

## What "passing DRC" means here

`signoff.py` runs DRC with `--no_density`: the layout is **geometrically clean** (0 spacing/
width/enclosure/latch-up violations). The full deck additionally flags metal/active/poly
**fill** and **min-density** rules (`M*Fil.h`, `AFil.g`, `GFil.g`, `M*.j`, `TM*.c`) — these are
satisfied by chip-level fill insertion at full-chip assembly, not on a standalone block, so
they are deferred (standard practice).

## Design notes / gotchas (hard-won)

- **Routing model:** horizontal per-net trunks on Metal2, vertical terminal stubs on Metal1,
  joined only where same-net by a `via_stack` (Via1). Since M1/M2 only connect through a via,
  different-net crossings are legal by construction. Gate poly is lifted to Metal1 by a
  `via_stack` (GatPoly→Metal1) poly contact; devices are spaced so each terminal owns a
  distinct x-column.
- **pmos returns 4 Metal1 boxes** (two stacked per finger) — cluster by x into 2 columns.
- **Bulk ties = raw diffusion taps** (Activ + pSD + Cont + Metal1), not the `ptap1`/`ntap1`
  PyCells, which extract as *resistor devices* and would pollute LVS.
- **LU.b latch-up:** every nmos must be within 20 µm of a p-substrate tie — intersperse taps.
- **LVS net labels** must be `Text` on **Metal2.text (10/25)** (or 8/25 for M1), and only the
  6 real ports should be labelled (labelling an internal net promotes it to a pin).
- **LVS reference** must use primitive `M` cards, not the `XM* … sg13_lv_nmos` subckt-instance
  form of the analog-db lowered netlist (that reads as a call to an undefined subcircuit).

## Automation-flow status & next steps

The end-to-end flow now runs **netlist → layout → DRC/LVS (×2 toolchains) → PEX →
post-layout sim → in-loop layout optimization**, all scriptable. Improvements the
gdsfactory lane already landed: port-driven routing, computed mirror-symmetric placement,
a 6× smaller parasitic UGF penalty, and a nevergrad fine-tuning loop with the full
toolchain as the evaluator (`optimize_layout.py` — the deterministic core of the
calibrate-by-feedback loop in the meta-repo's `doc/plan_layout_automation.md`).

Next steps, in rough order of value:

- **Generalize the placement engine**: extract the row/mirror-pair placer from
  `gen_5t_ota_gf.py` into a small library driven by a netlist + device-grouping spec
  (diff pairs, mirrors, cascodes tagged in `circuit.yaml`), reading sizing straight from
  `pdk/ihp-sg13g2/sizing.yaml` — the path to laying out other analog-db circuits.
- **Common-centroid / interdigitated patterns** for the matched pairs (currently plain
  mirror symmetry; fingering via the cells' `nf` parameter is the next matching step).
- **Channel router**: nets are still assigned to channels by hand; a simple
  net-to-track assigner over the row channels would make routing fully automatic.
- **Feed PEX back into the optimizer**: ~~post-layout metrics close the loop~~ done at
  the layout-constant level (`optimize_layout.py`), and now **through the platform
  optimizer itself** — `sim_engine: layout` (`spicexplorer.backends.layout`,
  `5t_ota_gf/opt/`): the flow is a testbench, DRC/LVS/PEX verdicts + post-layout registry
  metrics are target specs, `sizing_params:` routes sizing candidates into
  `build(params, sizing)` for a joint sizing+layout search.
- FasterCap engine for kpex (3D-solver accuracy); magic-native extraction remains a
  known gap; upstream the `ihp-gdsfactory` Via1 bug report.
- Decide whether to harden this into a `spicexplorer` leaf tool (`layout`/`gds`).
