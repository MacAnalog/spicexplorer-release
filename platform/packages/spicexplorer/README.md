# spicexplorer

The **circuit optimizer + the YAML DSL** — the first platform tool, which keeps the
historical `spicexplorer` import name. It turns a declarative project description (devices,
PVT corners, target specs, optimizer config) into a SPICE-in-the-loop optimization run and
the Plotly reports that visualize it.

**Layering:** sits directly above [`spicexplorer-core`](../spicexplorer-core) (re-using its
SPICE engine, `parse_value`, PVT primitives, `project_root`). The `spicexplorer-api` adapter
and `spicexplorer-orchestration` drive *this* package; it never imports an adapter or a leaf
tool. Import name: `spicexplorer` (distribution `spicexplorer`).

## Install / extras

Part of the `spicexplorer-platform` `uv` workspace (`uv sync`). **Library-only — there is no
CLI / console script.** The common single-objective & constraint optimizers and the *entire
scoring path* are pure `numpy` and import without any extra:

| Extra | Pulls | Enables |
|---|---|---|
| *(base)* | numpy + core | Nevergrad single-objective / constraint optimization, scoring, YAML DSL, viz |
| `[ax]` | `ax-platform` | Bayesian optimization (`optimization/stochastic/bayesian_ax.py`) |
| `[torch]` | `torch`, `control`, `sympy` | Bode / AC transfer-function fitting (the dormant RL optimizers also import these — but see the note below: RL needs an *additional*, undeclared dep) |

```bash
pip install 'spicexplorer[torch]'   # only if you need Bode fitting or the RL path
```

> **RL is dormant.** Everything under `optimization/rl/` (DDPG/SAC/TD3 agents, replay buffer,
> `rl_optimizer`) is wired but not part of the active flow, and it hard-imports `stable-baselines3`,
> which is declared in **no** extra — so RL is not runnable as shipped (`[torch]` is necessary but not
> sufficient). The supported optimizers are the Nevergrad family and (optionally) Ax.

## Import surface

This package has **no top-level `__init__.py`** — import from the subpackages:

```python
from spicexplorer.core.domains import Project_Setup
from spicexplorer.optimization import Circuit_Optimizer_Orchestrator_with_SPICE
from spicexplorer.viz import Optimization_Log_Visualizer
```

### `spicexplorer.core` — the YAML DSL + scoring

`core/domains.py` holds the typed dataclasses that *are* the YAML schema (it also re-exports
the carved-out core primitives — `Corner`, `PVTConfig`, … — so legacy call sites keep working):

| Symbol | Role |
|---|---|
| `Project_Setup` | Top-level project. `Project_Setup.from_yaml(path)` parses + resolves the project; `ws_root` is the design's workspace root (examples ship `ws_root: ..`; a leading `~` is expanded; resolved for portability). **DUT-parameterization projection (P3, meta `doc/plan_parameterization.md` D-5):** the optional `params_file:` key points at the circuit's `abstract/params.yaml` (`spicexplorer/params@1` — atomic inventory + shipped tying; relative → `ws_root`, like `netlist`). With it set, a `dut_params` name may be `<group>.<field>` (resolved at load to the group's **FIRST member's** atomic symbol — the free knob under the D-3 lowering, where a tie is just `.param <member> = {<first_member>}` in the deck) or a bare group name when the group ties exactly one field; and the optional `ungroup:` selector list (`"<group>"` \| `"kind:<kind>"` \| `"ratio:<ref-instance>"`) dissolves shipped ties by appending **frozen** shadow dut_params — one explicit `.param <member_symbol> = <current default>` per dissolved non-first member-field (*untying = shadowing*, values read from the project `netlist`'s own `.param` header; a dissolved `ratios:` entry freezes the derived symbol at `param(of) × ratio`). The frozen shadows ride the optimizer's existing verbatim `.param` rewrite (`NevergradMixin` injects frozen vals — zero optimizer-core changes, both engine lanes), and a shadowed symbol the projection already lists as its own dut_param stays a FREE knob. Both keys absent → exactly the legacy load; `resolve_param_projection()` is the hook after programmatic construction. Default posture stays low-dimensional (~5–8 curated knobs) — atomic granularity is *availability*, not the default search space. Semantics live in `backends/params.py`; offline `tests/test_params_projection.py`. |
| `TechSpec` | PDK / technology block. |
| `Param`, `TestbenchParams` | Swept device/testbench parameters (with freeze + bound semantics). A testbench is defined by its `netlist:` file — for `sim_engine: spectre` a native Spectre `.scs`, exactly as ngspice uses a `.spice` (no Spectre-specific YAML shape). |
| `TargetSpec`, `ListTargetSpec` | Optimization targets. **Gotcha:** `project.optimizer_config.target_specs` returns a `ListTargetSpec`, **not** a plain list — use `.targets` to reach the underlying list. Optional **`measurement:`** is a declarative metric recipe, validated at load, and merged back under the spec's `name` so the scorer seam is unchanged. Three shapes: **Tier-1 engine-neutral Python** — `{meas: <name>, …args}` (e.g. `meas: pm, out: v_out`; `meas: i_supply, probe: 'i(vvdd)'`), computed from the result's own waves by `spicexplorer_core.measurements` for **both** ngspice and Spectre; **Tier-2 OCEAN** — `{result, expr}` (raw) or `{builder, …args}` (a named `ocean_metrics` constructor), Spectre only; and **param-derived** — `{derived: <name>, …args}` (e.g. `derived: active_area, devices: [{w, l, m?}, …]`), a figure computed from the *candidate sizing* with NO simulation (active area = `Σ W·L·m`), scored like any metric. `measurement_tier()`/`has_python_measurement()`/`has_ocean_measurement()`/`has_derived_measurement()` discriminate. |
| `OptimizerConfig` | Optimizer selection + budget + the target specs. |
| `OptimizationLog`, `OptimizationLogEntry`, `OptimizationPoint` | The run log fed to the visualizer. |
| Enums | `SimType`, `SpiceSimulatorType`, `OptimizationGoalType`, `OptimizerType`, `Error_Types`, `Reward_Types`, `NoiseType`, `AgentType`. |
| RL config | `DDPGConfig`, `SACConfig`, `NetworkConfig`, `RLTrainingConfig`, … — used only by the dormant RL path. |

Also: `core/utils.py` (scoring math + `aggregate_corner_scores`/`CORNER_SCORE_AGGREGATORS`
— the multi-corner collapse registry), `core/tf_models.py` (transfer-function models for
Bode fitting).

**Multi-corner PVT (Phase 2)**: with `pvt.mode: multi` in the YAML, every trial runs the
{enabled testbenches} × {enabled corners} cross-product and collapses the per-corner
scores via `pvt.score_aggregation` (`mean` | `sum` | `min`). Aggregation is
**constraint-first**: if any corner fails, only the failing corners' penalties collapse
(a passing corner's reward can't mask a PVT violation). Multi-mode `fit_summary`
keys are `"<corner>::<spec>"`; per-corner totals ride in each log entry's
`point.metadata` (`corner_scores`, `score_aggregation`). See the guide notebook
[`examples/notebooks/multi_corner_pvt_optimization.ipynb`](../../examples/notebooks/multi_corner_pvt_optimization.ipynb)
and [`doc/PVT_plan.md`](../../doc/PVT_plan.md).

**Checkpoints are crash-safe and round-trippable**: `save_checkpoint` writes atomically
(via `spicexplorer_core.atomic_io`), so a process killed mid-autosave leaves the previous
complete checkpoint intact rather than a torn JSON the next resume can't parse. Each
entry's `log_file` serializes as a plain dict, so `Base_Optimizer.load_checkpoint` (and
the viz reader) round-trip a real run — including resume across a re-enumerated corner set.

## The central workflow

```
YAML  →  Project_Setup.from_yaml()  →  Circuit_Optimizer_Orchestrator_with_SPICE
      →  NGSpice testbench execution  →  scorer  →  checkpoints + Optimization_Log_Visualizer
```

```python
from spicexplorer.optimization import (
    Circuit_Optimizer_Orchestrator_with_SPICE, Optimizer_Type_Enum,
)

# The orchestrator takes the YAML *path* + the optimizer kind (it calls from_yaml itself):
orchestrator = Circuit_Optimizer_Orchestrator_with_SPICE(
    project_setup_path="examples/OTA/cascode/ihp-sg13g2/sizing/project_setup.yaml",
    optimizer_type=Optimizer_Type_Enum.NEVERGRAD_SINGLE,
    auto_load=False,
)
orchestrator.initialize()                 # parse the YAML + build the SPICE wrappers
optimizer = orchestrator.get_optimizer()
optimizer.parameterize()                  # declare the search space from the DSL
log = optimizer.optimize(render_optimization_trace=False, keep_history=False)  # → OptimizationLog | None
```

> Requires a live ngspice **and** a PDK to actually simulate (`probe_env()["pdk_ok"]`). On a
> PDK-less host the run degrades — do real optimization in the Docker `api` container or the
> research server.
