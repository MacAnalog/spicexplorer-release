# spicexplorer-netlist2xschem

Turn a SPICE netlist into an **xschem schematic** (`.sch`) — and, when xschem is available, render it
to **SVG/PNG**. The generated `.sch` is viewable directly in the SpiceXplorer UI's xschem viewer (no
image step needed); image export is additive.

A **leaf tool**: it reads the netlist through `spicexplorer_core.spice_engine.NetlistView` and depends
on `spicexplorer-core` only — never on a peer tool.

## How it works

`ingest → analyze → map → place → wire → emit`:

1. **ingest** — parse the netlist (`NetlistView`) into a small device model (pin → net per device),
   capturing a descended subckt's formal ports. Typing is by reference-designator prefix, `X…`
   included (`XM1` is a MOSFET, not a subcircuit) — but an `X` reference whose net count does not
   fit its primitive falls through to the generic SUBCKT branch instead of being dropped, so a PDK
   primitive shipped as a subcircuit with an extra node (IHP's 3-net `XR1 a b sub rhigh`) is
   modelled with all its nets.
2. **analyze** (`analysis.py`) — topology: supply rails, a vertical rank per net (VDD→VSS along the
   current path), matched differential pairs, an L/R/centre side per device, circuit-I/O **ports**,
   and **gate-sharing** device pairs.
3. **map** — each device → an xschem symbol: IHP MOSFETs → `sg13g2_pr/sg13_lv_{n,p}mos.sym`;
   R/C/L/V/I → the bundled `devices/*.sym`; PDK primitives shipped as subcircuits → the
   `_PDK_SUBCKT_SYMREF` table (SG13G2 HBTs and the `rhigh`/`rppd`/`rsil` poly resistors). Those
   resistors are 3-node subckts drawn with a **2-pin** symbol: their `format` line reads
   `@spiceprefix@name @pinlist @body @model w=@w l=@l …`, so `mapping.body_pin()` routes the
   substrate node onto the instance's `body=` attribute instead of a wire, and the netlist round
   trip reproduces all three nets. An unsized instance is left unsized — the emitter never
   back-fills `w`/`l` from the symbol template (that default is the symbol author's, not the
   model's: `rhigh.sym` says `l=0.5e-6`, the model library's `.subckt rhigh` says `0.96e-6`) and
   warns instead; any other parameter rides along on the instance with a warning that the fixed
   `format` line will not netlist it back. Any other subckt still resolves to `None` and is skipped with a
   "no symbol mapping" warning. **By default the device's sizing text is suppressed** —
   each maps instead to a clean *no-params* twin (`devices/*_np.sym`, generated by
   `symbol_gen.clean_symbol` and vendored beside the originals) that has identical pins + netlist
   `K`-block but draws no `w=…`/`l=…`/`model` text, so a topology schematic stays readable. The instance
   still carries the full values (it round-trips for netlisting). Pass `show_device_params=True`
   (CLI `--show-params`) to draw them.
4. **place** (`placement.py`, default `PhasedPlacer` — "the readable default") — a three-phase,
   level-banded layout. **(1) Rows from rails:** each MOSFET's row is its discrete longest-path
   **level** (VDD-source bank at top → a cascode one row below the device it stacks on → VSS devices at
   the bottom), so a multistage amp collapses to a handful of rows instead of sprawling. **(2) Columns
   from chains:** devices linked drain↔source through a *true series* node are unioned into a **chain**
   that shares one column — a cascode/output leg draws as a dead-straight vertical stack — and chains
   are ordered left-to-right by a **barycentre** heuristic so a mirror bank lands next to the stack it
   biases (a fan-out/summing node — diff-pair tail, output — is *not* a series link, so the signal path
   isn't collapsed); gate-shared devices are mirrored gate-to-gate. **(3) Passives then sources:** a
   2-terminal passive drops into its column (vertical) or bridges two columns (horizontal, e.g. a Miller
   cap), and independent **sources** (V/I bias/test) are parked **bottom-left**, connected by net-name
   only. With **no MOS devices** it falls back to `GridPlacer` (a plain deterministic grid).
   **`--placer` chooses the strategy** — `phased` (default), `topology` (rows by VDD→VSS rank, the
   two symmetric legs straddling the differential pair) or `grid`. Reach for `topology` when the
   default bands a whole circuit onto ONE level and draws it as a single very wide row; a mirror
   bank is the shape that does it. (Before, the CLI constructed the default and nothing else.)
5. **wire** (`wiring.py`, default `hybrid`) — *connectivity is DRAWN; a label NAMES a net, it is
   never the connection.*
   - **local** gate/source/drain nets are drawn as orthogonal **wires** (a stack vertical, or a trunk
     pushed into the channel beside the pins); where the straight join is refused, a **three-segment
     detour** round the obstacle is tried before anything falls back to a name (the drain/source tie
     that has to pass a body pin);
   - **supply** pins flush onto a VDD rail (top) / VSS·GND rail (bottom) via short stubs; a supply
     whose terminals are **all body pins** still gets its rail — it is the landmark a reader looks
     for first;
   - **circuit I/O** nets become `ipin`/`opin`/`iopin` **port symbols** placed on the **outermost end
     of their own net's drawn wiring** (inputs leftmost, outputs rightmost, bidirectional lowest), so
     the port IS the connection and the net is not drawn twice; a net with no drawn wire at all keeps
     the old pin parked at the frame, and those are reported (`parked_ports`);
   - **broad cross-circuit** nets (bias buses, the tail across both branches, mirror nodes) and
     **body (bulk)** pins carry a net-name label only — connected by name, the way they're drawn by
     hand;
   - asked for with `router="channel"` (`--router channel`), a **block diagram** (two or more block
     symbols, no MOSFET) is routed by channels instead: one rail per block row for each supply, one
     lane per net in each gap between blocks — see
     [Block diagrams: channel routing](#block-diagrams-channel-routing). Off by default.
   Every route is checked by `connectivity.py` against xschem's net-merge rules; any wire that would
   short two nets is dropped back to a net-name label, and a run whose endpoint would then hold
   **nothing** is dropped too (a wire drawn to nowhere reads as the connection, carries none, and
   hands xschem an unnamed island — a silent open). What is still joined by name rather than by wire
   is reported: `ConnectionPlan.by_name` / `ConnectionPlan.parked_ports`, surfaced on the emitted
   document as `SchDocument.nets_by_name` / `.parked_ports` and counted in the CLI's summary line.
   (`wiring="labels"` is the simplest mode — a label on every pin.)
6. **emit** — write the `.sch` text (deterministic).

The result reads like a hand-drawn schematic yet stays **correct**: it always renders and
**round-trips** — xschem re-netlisting a generated `.sch` reproduces the original device set and
connectivity (verified on 5T / telescopic / folded-cascode OTAs). The connectivity check means the
wiring can be aggressive for readability without ever shipping a short.

> **PDK scope (v1):** IHP `sg13g2` MOSFET symbols + the generic xschem device symbols. The symbol map
> in `mapping.py` is extensible to other PDKs once their xschem symbol libraries are vendored.

## Library usage

```python
from spicexplorer_netlist2xschem import from_file, build_sch

circuit = from_file("ota-improved.spice")  # NetlistView -> N2XCircuit (flat netlist)
doc = build_sch(circuit, pdk="ihp-sg13g2", title="ota")
print(doc.device_count, doc.label_count, doc.warnings)
open("ota.sch", "w").write(doc.text)  # open this in the UI's Schematic viewer

# Devices live inside a .subckt? descend into the instance:
core = from_file("ota-5t_tb.spice", into="xota", name="ota-5t")

# Render to an image (needs xschem; PNG also needs a rasterizer — cairosvg, rsvg-convert or magick):
from spicexplorer_netlist2xschem import render

result = render("ota.sch", fmt="png")  # -> RenderResult
# result.available is False (and image_path None) when xschem isn't on PATH — the .sch is still valid.
# result.rasterizer names which rasterizer drew the PNG; "imagemagick" means the lossy fallback.
```

### Hierarchy in, flat cell out (`hierarchy.flatten_hierarchy`)

The parent sheet of a block hierarchy netlists **as a hierarchy** — one `.subckt` per drawn block —
but the gate that proves *drawing == netlist* compares against the certified **flat** cell.

```python
from spicexplorer_netlist2xschem.hierarchy import flatten_hierarchy

r = flatten_hierarchy("amp_hier.spice", "amp_flat.spice", note="drawing of record")
r.spliced  # ('XBIAS -> bias_ref (3 devices)', 'XSTAGE -> gain_stage (3 devices)')
r.qualified_local_nets  # ('xbias.net1', 'xstage.net1')
```

Leaf instance names are **preserved** (`XM1` stays `XM1`), which is what lets the device-by-device
parameter join still work afterwards — a flattener that renames leaves to `xblock.XM1` produces a
netlist that is equivalent and unjoinable. A child's unlabelled nodes are auto-named per sheet, so
two children both own a `net1`; each is qualified with its instance. A leaf-name collision between
blocks and an internal-net collision both **raise** rather than merging two different nodes. All
parsing goes through `spicexplorer_core.spice_engine.NetlistView` (net tokens found by position,
from the parser's own node count), so nothing here re-implements SPICE parsing.

### Block coverage, both directions

`BlockAnnotationSet.validate(circuit)` is the fail-closed half: an annotated device the circuit does
not have. `BlockAnnotationSet.coverage(circuit, loose=(...))` is the other half, which nothing else
checks — a device in **no** block at all, silently missing from every child sheet while the parent
still netlists and a topology gate (component and net counts) still passes. It reports rather than
raises; `loose` declares by name the cell-level devices that deliberately belong to no block (a
reference source, a loop-break marker, an output capacitor), so a NEW loose device is a finding.

### Helpers the schematic agent calls (off by default)

Channel routing (`router="channel"`, `--router channel`), `--collapse` and the measurement report
(`--report`) are helpers the schematic agent calls while it draws. They do not replace the agent:
placement, symbols, the hierarchy and a sheet a designer can read stay the agent's work, and the
agent decides what to keep. Each helper is off by default, and with default arguments every sheet
is written byte for byte as before the helpers existed (`tests/test_default_output.py` compares
95 sheets with digests recorded on that code).

### Block diagrams: channel routing

Asked for with `router="channel"` (`build_sch`, `plan_connections`, `build_collapsed_sch`) or
`--router channel`, a sheet with two or more block symbols and no MOSFET is routed by channels
(issue #243). A block symbol is a subcircuit instance drawn with a design's own `.sym`
(`mapping.register_subckt_symbol`), not a kit primitive's. Any other sheet is drawn by the
per-route planner even when channels are asked for, and the default, `router="per-route"`, never
routes by channels. `plan_connections` takes its routes from `channels.py`; the verifier, detours,
dangling-run rule, ports and labels are the per-route planner's code. `SchDocument.router` says
which one drew the sheet.

```python
from spicexplorer_netlist2xschem import build_sch, from_file, sheet_report
from spicexplorer_netlist2xschem.mapping import register_subckt_symbol

register_subckt_symbol("generic", "blk_a", "cells/blk_a.sym")  # one per cell, .sym on the path
doc = build_sch(
    from_file("top.spice", into="xtop"), pdk="generic", placer=my_floorplan, router="channel"
)
sheet_report(doc)["nets_by_name"]  # [] when every net is drawn by wire
```

**Algorithm**, run on the placement before any wire exists:

1. **Channels.** Device boxes (a block's `Symbol.bbox` with its pins) merge into column and row
   bands; each gap between bands, and the space outside the outermost band, is a channel.
2. **One lane per net per channel**, numbered by the left-edge algorithm, so nets with overlapping
   spans get distinct x (or y). Pins facing each other across a channel order their lanes (rule in
   the `channels.py` docstring).
3. **Supplies first.** One rail per block row on the track next to its taps, a spine in the outer
   channel (VDD left, VSS/GND right). Supply routes are verified first and held fixed, so a signal
   wire that touches a rail is the route refused.
4. **Fallback, counted.** A lane past capacity, a pin left out of an ordering loop and a refused
   route fall back to the net name, counted in `ConnectionPlan.by_name` and
   `SchDocument.nets_by_name`.

`build_sch` first widens each channel narrower than its lanes need ((n - 1) x 20 units between n
lanes, plus 20 on each side) by moving the blocks beyond it (`wiring.spread_channels`);
`plan_connections` alone moves nothing. Measured results are asserted in
`tests/test_channel_routing.py`, under both routers.

**Limits.**

- **Aligned rows and columns only**; otherwise two devices share a band cell and the per-route
  planner draws the sheet. Without `placer=`, a netlist with no MOSFET is placed by `GridPlacer`
  at a 240-unit pitch whatever the symbol size.
- **Side supply pins** get a lane, not a rail tap. **Labels** sit on a stub off the topmost pin, as
  on a cell sheet, and can overlap a lane.
- **A refused end stub removes its whole track or lane** (dangling-run rule), and the other pins on
  it fall back to their names.
- **Only a MOSFET marks a cell sheet**: an HBT primitive has no transistor pin role, so blocks with
  an HBT beside them are channel-routed.
- **Asked for channels, a sheet that falls back to the per-route planner** has its label stubs and
  detours checked against each block's drawn extent, not the 60 x 76 transistor box and its text
  band; net runs are not, and can cross the block. The default never uses the block extent.

### Repeated cells one level down (`--collapse`)

`--collapse` is a helper the agent asks for on a level with many repeated cells: it moves every
instance of the named cells into a new cell drawn one level down (issue #264). The top sheet
carries one instance of the new cell; the new cell's sheet carries the slices. No slice gets a
sheet of its own. Without `--collapse` nothing changes.

```bash
netlist2xschem top.spice --into xtop --pdk generic -o top.sch \
    --collapse front=blk_a,blk_b --collapse blk_c \
    --cell-symbol blk_a=cells/blk_a.sym --cell-symbol blk_b=cells/blk_b.sym ...
```

```python
from spicexplorer_netlist2xschem import (
    build_collapsed_sch, check_collapsed, parse_collapse, write_hierarchy)

groups = [parse_collapse("front=blk_a,blk_b"), parse_collapse("blk_c")]   # blk_c -> blk_c_bank
result = build_collapsed_sch(circuit, groups, pdk="generic", cell_symbols={"blk_a": sym_text, ...})
write_hierarchy(result, "out", parent_name="top")   # out/top.sch, out/blocks/front.{sch,sym}, ...
check_collapsed(result, circuit).identical          # the finished sheets flattened == the netlist
```

**Rules.**

- **Grouping is by cell name** (`CELL`, whose group is `CELL_bank`, or `GROUP=CELL[,CELL...]`), never
  by instance: a slice added to the netlist joins its group on the next run.
- **Ports are computed.** A net the slices touch is a port of the group cell when the netlist level
  declares it or any device outside the group touches it. A net between two slices, and a slice
  pin nothing else connects to, stays on the group sheet.
- **Pin sides come from the slice symbols**: a net on any slice's `out` pin goes right, VDD on top,
  VSS/GND at the bottom, every other net left. The group sheet draws exactly the symbol's ports
  with the same directions (`ipin`/`opin`/`iopin`); xschem reports an error for a sheet port whose
  direction differs from its symbol pin's.
- **Placement**: each sheet is a grid whose pitch clears its largest symbol by 120 units, then
  wired by the router asked for: the per-route planner by default, or channels on each block
  diagram with `--router channel` (previous section). `--placer` replaces the grid on every sheet.
- **Proof on every run.** `check_collapsed` extracts the connectivity of the finished sheets from
  their geometry (`virtuoso_export.netex.extract_nets`), flattens each group instance through its
  sheet and compares every (instance, pin) terminal and every declared port with the netlist, in
  both directions. It also counts the instances over all the sheets: one drawn twice (a slice on
  both the top sheet and its group sheet) is reported in `duplicate`, since its terminals alone
  compare equal. The CLI prints the counts and exits 1 on any difference.

**Files.** Group cells and the `--cell-symbol` copies are written to `blocks/` beside the top
sheet. The top sheet places them as `blocks/<cell>.sym`, a sheet inside `blocks/` as `<cell>.sym`:
xschem resolves a relative symbol path from the directory of the sheet that places it.

**Limits.**

- **One added level**: a group cell does not contain another group cell.
- **Subcircuit instances only**: a MOSFET or passive at the level stays on the top sheet.
- **A cell with no symbol is not drawn** (no `--cell-symbol`, nothing registered); the check then
  reports its terminals missing and the CLI exits 1.
- **A registered symbol keeps its symref** on a group sheet, so xschem finds it there only through
  a library-path entry that is not `.` (which is `blocks/` for that sheet); `--cell-symbol` avoids it.
- **Fewer than two instances form no group** (a warning).
- **No functional icon on a group cell** (`--icon` needs `--hierarchical`).
- **The channel router's limits apply on each sheet** when it is asked for; one grouping measured
  in `tests/test_collapse.py` leaves 3 nets to their names on one group sheet.
- **A leaf cell's `.sch` is looked up in the top sheet's directory**, also for a cell placed on a
  group sheet in `blocks/`. Measured with xschem 3.4.4: `blocks/blk_a.sch` is not found for the
  `blk_a` slices on `blocks/front.sch`, and xschem writes `.subckt blk_a` with no devices, exit 0
  and only an "unable to open" log line. `blk_a.sch` beside the top sheet is found. A cell placed
  on the top sheet is found in `blocks/`. A design that supplies leaf schematics puts each
  grouped cell's `.sch` beside the top sheet.
- **Node 0 is a port like any other net**: when the slices and anything outside the group touch
  `0`, the group cell gets a pin named `0` (at the bottom, a GND net); the `--hierarchical` lane
  computes a block's pins by the same rule. The flatten check compares it like any other net.

### Measurements for the agent (`report.py`, `--report`)

A drawn sheet does not show which nets are joined by a wire and which only by their name labels.
`sheet_report(doc)` returns what the agent needs to decide what to redraw, `collapse_report(result,
check)` adds each group and the flatten check, and `--report FILE.json` (`-` for standard output)
writes the same JSON from the CLI. The `.sch` files are the same with or without it.

| key | what it holds |
|---|---|
| `router` | the router that drew the sheet: `per-route`, `channel`, or `labels` |
| `nets_by_name`, `nets_by_name_count` | nets whose pins the drawn wires leave in more than one piece, and the nets of port pins parked at the frame |
| `pieces` | for each of those nets, the number of drawn pieces its pins fall into |
| `parked_ports` | port pins with no wire of their net to sit on, parked at the frame |
| `lanes` | lanes reserved per channel, `v:<i>` (0 is left of the first block column) and `h:<j>` (0 is above the first row); channel router only |
| `unrouted` | nets the channel router left to their names before any wire was checked: a lane past its channel's capacity, or a pin taken out of an ordering loop |
| `supply` | per supply net: `rails`, `spines` and `taps` drawn, and `refused` (planned supply wires the connectivity check or the dangling-run rule removed) |
| `groups`, `top_sheet` (`--collapse`) | each group's instance, slices and ports; the top sheet's instances before and after |
| `check` (`--collapse`) | `identical`, `terminals`, `nets`, and every `split`, `merged`, `missing`, `extra`, `duplicate` and `port_mismatch` |

## CLI usage guide

Installed as the `netlist2xschem` console script:

```
netlist2xschem INPUT.spice [-o OUT.sch] [--pdk ihp-sg13g2] [--into XINST]
               [--name NAME] [--router per-route|channel] [--report FILE.json|-]
               [--render none|svg|png] [--out-image PATH]
```

| flag | meaning |
|------|---------|
| `INPUT.spice` | input SPICE netlist (`.spice`/`.cir`/`.net`/`.sp`) |
| `-o, --out` | output `.sch` path (default: `<input stem>.sch` beside the input) |
| `--pdk` | target PDK for MOSFET symbols (default `ihp-sg13g2`) |
| `--into` | descend into this subckt **instance** before generating (e.g. `--into xota`) |
| `--name` | schematic name / title (default: the netlist stem) |
| `--annotations` | a `spicexplorer/xschem-block-annotations@1` JSON of recognised functional blocks to outline as labelled boxes; **also drives the placement by block** (see below) |
| `--no-block-placement` | with `--annotations`, draw the boxes over the default layout instead of clustering each block (block-aware placement is on by default) |
| `--placement` | with `--annotations`, how blocks drive the flat layout: `block-aware` (default), `template-stamp` (lay each block at its hand-drawn symmetric template), or `flat` |
| `--placer` | device placement strategy: `phased` (default), `topology`, `grid`. Independent of `--placement`, which only says how annotation blocks influence whichever placer is chosen. With `--collapse` the default is a grid whose pitch clears the largest symbol on each sheet |
| `--router` | how the wires are planned: `per-route` (default; every sheet as it has always been drawn) or `channel`, a helper for a top level of block symbols that routes each block diagram by channels — see [Block diagrams: channel routing](#block-diagrams-channel-routing). Flat sheet and `--collapse` sheets only |
| `--report` | also write the measurements of what was drawn as JSON (`-` for standard output) — see [Measurements for the agent](#measurements-for-the-agent-reportpy---report). The `.sch` files are unchanged. Flat sheet and `--collapse` sheets only |
| `--dark` | render on xschem's dark colour scheme. The default is **light**, because a sheet of record is read on a white page |
| `--hierarchical` | with `--annotations`, emit a **true xschem hierarchy** — each block becomes a child `.sch` + subcircuit symbol and the parent instantiates them (writes a sibling `blocks/` dir) |
| `--icon` | with `--hierarchical`, draw a block with its **functional icon** instead of a plain box: `--icon sar_cmp=comparator` (repeatable; `<icon>@<scale>` to enlarge a small block). The cell netlists unchanged (pins byte-identical at the same scale) — see [Functional icons](#functional-icons-an-opamp-is-a-triangle-not-a-rectangle) |
| `--no-auto-icons` | with `--hierarchical`, do not map a recognised block type to its icon; draw only the blocks named by `--icon` |
| `--collapse` | move every instance of a cell one drawing level down into a new cell whose sheet carries them: `--collapse blk_a` (cell `blk_a_bank`) or `--collapse front=blk_a,blk_b` (repeatable). Writes the group cells to `blocks/` beside `-o`, flattens the finished sheets and exits 1 unless the connectivity equals the netlist's. See [Repeated cells one level down](#repeated-cells-one-level-down---collapse) |
| `--cell-symbol` | with `--collapse`, the `.sym` every instance of a cell is drawn with: `--cell-symbol blk_a=cells/blk_a.sym` (repeatable; copied into `blocks/`) |
| `--annotate-existing` | treat `INPUT` as an existing `.sch` (not a netlist) and just overlay the `--annotations` boxes on its current layout, moving nothing |
| `--show-params` | draw each device's parameter text (`model`, `w`/`l`, `value`). **Off by default** — devices use clean *no-params* symbols (the runnable values are still carried for netlisting) |
| `--render` | also export an image via headless xschem: `none` (default), `svg`, or `png`. The render is judged by its **content**: xschem exits 0 and writes a valid background-only SVG when it could not read the sheet, and that is reported as a failure, not a success |
| `--out-image` | where to write the image (default: alongside the `.sch`) |
| `--title-block` | draw a **title block** (frame + cell / design / rev / date / author) clear of the drawing, instead of the loose title text — see [Title block](#title-block) |
| `--cell` `--design` `--rev` `--author` | the block's fields (all optional but `--cell`, which defaults to the schematic name); an empty field draws no row |
| `--date` | the block's date, **verbatim**. Default: `SOURCE_DATE_EPOCH`'s UTC date if set, else today — and the value used is printed |
| `--title-block-corner` | which corner of the drawing's extent the block sits at: `bottom-right` (default), `bottom-left`, `top-right`, `top-left` |

Examples:

```bash
# generate a .sch only (works anywhere — no xschem needed)
netlist2xschem ota-improved.spice -o ota.sch

# generate + render an SVG (needs xschem on PATH)
netlist2xschem ota-improved.spice -o ota.sch --render svg

# descend into a subckt instance and render a PNG (needs xschem + the [render] extra)
netlist2xschem ota-5t_tb.spice --into xota -o ota5t.sch --render png --out-image ota5t.png

# outline recognised functional blocks (current mirrors, diff pairs) over the placement
netlist2xschem ota.spice -o ota.sch --annotations ota.blocks.json --render svg

# a hierarchy whose blocks are drawn as what they ARE (triangle, staircase, pass device…)
netlist2xschem adc.spice -o adc.sch --hierarchical --annotations adc.blocks.json \
    --icon sar_cmp=comparator --icon cdac=dac --render svg
```

`--pdk` also scopes the symbol search path and the generated `xschemrc`: only `ihp-sg13g2` is
vendored here, and naming another kit leaves that library out — a commercial-kit design's own
denylist trips on it.

If `--render` is requested but xschem isn't on `PATH`, the `.sch` is still written and the image step
is skipped with a note — the `.sch` renders in the SpiceXplorer UI's viewer regardless.

## Title block

**The rule: a sheet is a function of its inputs — so the title block's date is an ARGUMENT, never a
clock.** `add_title_block` draws the block itself (issue #265):

```python
from spicexplorer_netlist2xschem import add_title_block, build_sch, TitleBlock

text = add_title_block(
    sch_text, cell="ota5t", design="dn-000-demo", rev="b3", date="2026-09-21", author="A. Designer"
)  # str in, str out
doc = build_sch(
    circuit,
    title="ota5t",  # ... or from the emitter,
    title_block=TitleBlock(cell="ota5t", date="2026-09-21"),
)  #     replacing the loose title
```

```bash
netlist2xschem ota.spice -o ota.sch --render svg \
  --title-block --design dn-000-demo --rev b3 --date 2026-09-21 --author "A. Designer"
```

* It draws a frame (`L`, layer 3 — dark in both colour schemes) and one `T` record per field, at sizes and cell widths it
  computes, and places the whole block **clear of the drawn extent** in the chosen corner. The block
  scales with the sheet, so it keeps the same share of the page — and the same fields-to-frame
  geometry — whether the sheet is 400 or 20000 units wide.
* The **date is a string the caller supplies**. `title_block_date()` is the CLI's default
  (`SOURCE_DATE_EPOCH` if set, else today) and the value used is printed. Nothing else is read from
  the environment: no `$USER` author, no `git describe` revision.
* Rendering the same `.sch` twice, hours apart, therefore gives **byte-identical** SVGs — tested,
  with xschem's own `devices/title.sym` on the same sheet as the control that *does* churn.

The rule, and the measurements behind it, are stated once in
[`doc/schematic_title_block.md`](../../doc/schematic_title_block.md).

Why not `devices/title.sym`, the obvious thing to place? Two reasons, both of them properties of
that symbol (which stays available for anyone who wants it):

* its `@time_last_modified` is substituted from the **`.sch` file's mtime**, so a no-op regeneration
  rewrites every SVG and PNG with a new `HH:MM:SS` (146 files churned on one design). Setting
  `time_last_modified=` on the *instance* does not override it — the token is filled from the file
  and the attribute is stored and ignored. `@path @schname_ext` likewise prints the absolute path of
  whichever checkout drew the sheet;
* its date is drawn `flip=1` (xschem's right-anchor), and **a `flip=1` record does not survive the
  export zoom**: measured on xschem 3.4.4, the offset it gets is a constant number of *pixels*
  (`25.5 * size * len`) while the glyphs scale with the sheet — one 11-character size-0.16 label
  shifted 44.88 px on sheets 400 … 20000 units wide, i.e. 18.5 schematic units on the small sheet
  and 925 on the large one. That is why the date lands on `@author`, or through the symbol's own
  logo, on a large sheet and not on a small one. Nothing this package emits uses `flip=1` on a `T`
  record for that reason (see also `symbol_gen`, issue #266).

## Functional-block annotation overlay

Once an upstream detector recognises the **functional sub-circuits** in a netlist, it can hand them to
this tool to draw **labelled, coloured bounding boxes** over the schematic — proof the structural
pipeline fired, and a debugging aid for reading larger circuits. The overlay is purely diagnostic: it
adds xschem graphic rectangles (`B`) + text (`T`) and **moves no device and adds no wire**, so the
schematic's connectivity round-trip is unchanged.

It is **decoupled by a neutral contract** — the `spicexplorer/xschem-block-annotations@1` JSON. This
tool never imports the detector; any producer that emits the schema can drive the overlay (one is
`spicexplorer_circuitgraph.export_subcircuit_annotations`). A block lists the **device instance refs**
it contains — the join key against the placed schematic. Subsumed sub-blocks (a simple mirror inside a
cascode) nest as smaller **dashed** inner boxes; templates matching the same devices appear in the
label as `[alt: …]`.

```python
from spicexplorer_netlist2xschem import BlockAnnotation, BlockAnnotationSet, build_sch, from_file

aset = BlockAnnotationSet(
    (
        BlockAnnotation(
            "cm.nmos.simple#1",
            ("XM5", "XM6"),
            label="current mirror (nmos)",
            family="current_mirror",
        ),
    )
)
doc = build_sch(from_file("ota.spice"), annotations=aset)  # block-aware placement + boxes
# or load the JSON a detector wrote:  BlockAnnotationSet.load("ota.blocks.json")
```

End to end with the `circuitgraph` detector as the producer:

```python
from spicexplorer_core.spice_engine import NetlistView
from spicexplorer_circuitgraph import (
    CircuitGraph,
    find_subcircuits,
    group_matches,
    write_subcircuit_annotations,
)

g = CircuitGraph.from_netlist(NetlistView.from_file("ota.spice"), name="ota")
write_subcircuit_annotations(group_matches(find_subcircuits(g)), "ota.blocks.json")
# then: netlist2xschem ota.spice -o ota.sch --annotations ota.blocks.json --render svg
```

### The `@1` contract

**Where it is defined.** The schema is defined HERE — `ANNOTATION_SCHEMA` and `BlockAnnotation` in
[`annotation.py`](src/spicexplorer_netlist2xschem/annotation.py). circuitgraph's
`export_subcircuit_annotations` builds the annotation dict and keeps a byte-identical copy of the
string (neither package imports the other). A field change is agreed here first, then emitted there.

**Shape.** `{"schema": "spicexplorer/xschem-block-annotations@1", "blocks": [ … ]}` (a bare list of
block entries is also accepted). Per block, as circuitgraph emits it today:

| Field | Required | Read by this package |
|---|---|---|
| `block_id` | yes | every renderer — unique within the set |
| `devices` | yes | every renderer — host instance refs, the join key |
| `label`, `family`, `parent_id`, `alternates` | no | box overlay: text, colour group, nesting, `[alt: …]` |
| `template_id`, `role`, `polarity` | no | carried metadata |
| `template_sch`, `device_slots` | no | template stamping (`--placement template-stamp`) |
| `port_names` | no | `--hierarchical` output: a generated block symbol's pin names |
| `rules_ref`, `roles` | no | not read — for downstream agents; `to_dict()` does not write them back |

**Compatibility policy.**

- **Additive fields keep `@1`.** A new optional field needs no version change; every consumer ignores
  keys it does not know. A producer may label such a revision `@1.<n>`; it still reads as `@1`.
- **Anything a `@1` reader would misread is `@2`:** a renamed or removed field, a changed meaning or
  type, a new required field, a different join key. Ship `@2` from the producer only after this
  consumer reads it, and keep emitting `@1` until then.
- **Enforced on load.** `BlockAnnotationSet.from_dict` / `from_json` / `load` raise `ValueError` on a
  `schema` other than major `@1`, and on a mapping with no `blocks` key. The second check catches a
  real case: analog-db's `<id>.structural.json` carries this schema string but keeps its
  detections under `groups`, and used to load as an empty overlay. A payload without a `schema` key
  is still accepted.

### Block-aware placement

By default the blocks don't just get boxed — they drive the **placement**. When `annotations` are
supplied, `build_sch(circuit, annotations=…, annotation_aware_placement=True)` (the default) feeds the
blocks to the placer as `PlacementHints`, and each block's devices are **clustered** into a tight,
mostly-separate region under its box instead of being scattered by raw topology. It is a layout-only
hint — connectivity is identical either way (a Docker `xschem -n` round-trip confirms the placed
`.sch` re-netlists to the same circuit with or without it). On the multi-stage amplifiers this cuts the
total block-box overlap by ~50% (one case −77%).

Pass `annotation_aware_placement=False` (CLI `--no-block-placement`) to keep the older block-agnostic
layout and draw the boxes *over* it. Some residual overlap is inherent: blocks stacked in one current
path (a folded cascode's load / pair / mirror) share columns, so their axis-aligned boxes meet where
the stack does — colour + label still disambiguate. See `notebooks/annotation_demo.py`.

### Two further block-driven strategies (`placement_mode` / `--hierarchical`)

When the same blocks should drive the layout more strongly, two additional modes are available — both
**connectivity-neutral** (verified by an `xschem -n` round-trip; only coordinates / hierarchy change):

- **Template stamping** — `build_sch(circuit, annotations=…, placement_mode="template-stamp")` (CLI
  `--placement template-stamp`). Each block is laid out at the **hand-drawn, symmetric template** shipped
  beside it (`examples/analog-db/templates/…/<block>.sch`): we reuse *only its geometry* (each device's
  `x/y/rot/flip`) and let the normal wiring engine connect by net. A differential pair's halves come out
  **mirror-symmetric**, a cascode stacks straight. Needs the contract's `template_sch` / `device_slots`
  fields (`circuitgraph` emits them); a block lacking them falls back to block-aware.

- **True hierarchy** — `build_hierarchical_sch(circuit, annotations)` → a `HierarchicalResult` (parent
  text + child `.sch`/`.sym`), materialised by `write_hierarchy(res, dir)` (CLI `--hierarchical`). Each
  top-level block becomes its own child schematic + a generated `type=subcircuit` symbol, and the parent
  instantiates the block symbols — the readable "block diagram" view, each box openable. The block
  symbol's pins are **named by the template's functional port** (`out` / `ref_in` / `supply` / `in_p` /
  …, a fanned-out mirror's extra outputs numbered `out_2`, `out_3`, … — from the contract's `port_names`
  map), while each pin's *connection* name stays the host net so it still netlists. The parent is laid
  out rail-aware — block symbols in a centred row (VDD pins on top, VSS on the bottom), loose devices
  banded by rail affinity, independent **sources grouped** bottom-left — and **connections are shown by
  render-time net colouring**: every pin grows a short stub + a net-name label, and the renderer paints
  each net's stubs/labels one colour, so two same-net pins read as one node without a wire tangle.
  `xschem -n` descends into the children and re-netlists to the original flat circuit.

### Functional icons (an opamp is a triangle, not a rectangle)

A top sheet of forty identical boxes is a netlist with corners. The standard analog blocks have a
drawing every analog engineer reads at a glance, and the platform ships it once for every design:
`spicexplorer_netlist2xschem/symbols/analog_icons/` (issue #264).

| icon | drawn as | aliases |
|---|---|---|
| `opamp` | amplifier triangle, `+`/`-` beside the input pins | `ota`, `amp`, `amplifier` |
| `comparator` | triangle + `+`/`-` + a clock wedge on the strobe pin | `cmp`, `comp` |
| `integrator` | the response that defines it: step in, ramp out | `int` |
| `chopper` | the two crossed switch paths + a clock wedge | `commutator`, `mixer` |
| `adc` | a continuous ramp in, a staircase (a code) out | `a2d` |
| `dac` | a staircase in, a continuous ramp out | `d2a` |
| `ldo` | series pass device, error amplifier, feedback path | `regulator` |
| `switch` | an open blade between two terminals + its control clock | `sampler`, `transmission_gate`, `tgate` |

**How a design asks for one.** In the hierarchy lane, by cell / block id / template id / family:

```bash
netlist2xschem cell.spice --hierarchical --annotations blocks.json \
    --icon sar_cmp=comparator --icon reg=ldo@1.6        # repeatable; @<scale> is optional
```

A *recognised* block type is mapped automatically where the mapping is unambiguous (today:
`transmission_gate` → `switch`, plus any producer that emits a functional `family` of its own —
`comparator`, `ldo`, …). A recognised type that does not map unambiguously — a differential pair is
one **stage** of an amplifier, not an opamp — is left as the plain box; recognition that returns
nothing for a cell leaves it alone. `--no-auto-icons` turns the mapping off; an `--icon` that
matched no block is reported as a warning, never silently dropped. The run prints what it drew
(`icons: sar_cmp=comparator, …`), so "how much of this sheet still reads as rectangles" is visible.

For a design's **own** cells (outside the hierarchy lane), call the library directly:

```python
from spicexplorer_netlist2xschem import BlockPin, generate_icon_symbol

sym = generate_icon_symbol(
    "sar_cmp",
    [
        BlockPin("clk", "left"),
        BlockPin("vin", "left"),
        BlockPin("vip", "left"),
        BlockPin("vout", "right", "out"),
    ],
    "comparator",
)
(out / "sar_cmp.sym").write_text(sym.text)  # beside sar_cmp.sch
print(sym.warnings)  # what the glyph declined to draw, e.g. unidentifiable +/- inputs
```

**Why the symbol is written PER CELL, not shared.** For a `type=subcircuit` symbol, xschem binds the
child schematic to the **symbol FILE's basename**, not to the master the netlist ends up with. A
sheet that places one shared `comparator.sym` for cell `sar_cmp` netlists an *empty* `.subckt
comparator` (the real cell is never descended into) and, with a `@value`-style format line, an extra
`value` port on top — so the call has N nets while the cell declares N+1 and the hierarchy stops
round-tripping. `schematic=<master>` on the instance makes xschem descend correctly and *still*
emits the empty block and the extra port. So the **glyph** is shared (it is code) and the `.sym` is
written per cell with the stock `@symname` format. First measured by the design that hit it (#264)
and **reproduced as a test here** (`test_a_shared_icon_file_cannot_be_placed_…`), so the rule cannot
quietly be "simplified" away later.

**Why an icon cannot break gate 1 or gate 3.** An icon replaces the body `L` lines of the generated
block symbol and **nothing else**: at the same scale every `B` pin record, every stub and every pin
label is the plain symbol's, byte for byte (asserted per icon), so no pin can move, be renamed or be
reordered; scaled up, the coordinates move together and the names, order and directions still
cannot. A two-level hierarchy is netlisted by real xschem with and without each icon in turn, and
the two netlists are compared as text — identical, every icon.

**Marks are read from the pin list, never from a position.** A `.subckt` header that lists
`clk vin vip` puts the *inverting* input above the non-inverting one, so a `+` drawn at a fixed
"upper third" marks the wrong pin — and re-netlists perfectly while doing it. `+`/`-` are drawn only
when exactly one pin names itself non-inverting and exactly one names itself inverting; otherwise
neither is drawn and a warning names the pins that were looked at. Same rule for the clock wedge.

**Per-icon scale.** The body is sized from the **pin count**, so a 7-pin comparator beside a 56-pin
array comes out at a fraction of the sheet's width. Each icon carries a default scale, and
`--icon <cell>=<icon>@<scale>` (or `generate_icon_symbol(..., scale=…)`) overrides it. Scale moves
the geometry only — pitch, margins, stub, minimum extents — never a pin's name, side or order.

**Adding a glyph upstream.** Write the function in `symbols/analog_icons/glyphs.py` — it takes the
`IconFrame` (the body box and its pins, already computed from the pin count) and returns an
`IconDrawing(outline, detail, notes)`: `outline` is the shape a pin lead may attach to, `detail` is
everything drawn inside, `notes` is what it *refused* to guess. Use `L` records only (every consumer
reads lines: xschem, the Studio viewer, `xvport`'s Virtuoso port) and keep it ASCII. Register it in
`ICONS` with its aliases and scale; it joins the round-trip and byte-identity tests automatically
(they are parameterised over the registry). Add a `FAMILY_ICONS` entry only when the mapping from a
recognised block type is unambiguous.

Side-by-side renders of all three on four amplifiers are in the `analog-db` raw export gallery (the `_block_placement_strategies` subdirectory, which has since been removed from the committed tree).

### Annotate an existing (hand-drawn) schematic

`annotate_sch(sch_text, annotations)` (CLI `--annotate-existing`) overlays the block boxes on a
schematic **you already have** — hand-drawn or exported — without regenerating it: it parses the `.sch`
for each device's placed coordinate and draws the boxes over that layout, moving nothing (the output is
the input byte-for-byte plus appended `B`/`T` graphics). Blocks are joined to the drawn devices by
instance name (tolerant of the `XM3`↔`M3` spiceprefix split); a block whose devices aren't in the
drawing is skipped with a warning. This is the **manual path** — it respects your layout — as opposed
to the auto-generation path above (netlist → placement → boxes), which *creates* a layout and is
best-effort on complex circuits.

```bash
# blocks.json: hand-authored, or exported by circuitgraph's write_subcircuit_annotations(...)
netlist2xschem ota.sch --annotate-existing --annotations blocks.json -o ota.annotated.sch
```

```python
from spicexplorer_netlist2xschem import BlockAnnotationSet, annotate_sch

annotated, warnings = annotate_sch(sch_path.read_text(), BlockAnnotationSet.load("blocks.json"))
out_path.write_text(annotated)
```

## Virtuoso porting (`xvport`)

> **Dedicated user guide:** [`doc/guide_xvport.md`](../../doc/guide_xvport.md)
> (task-oriented: setup, forward/reverse recipes, device-map authoring, the e2e checks,
> NDA rules, troubleshooting, CLI reference). This section is the API-surface summary.

`spicexplorer_netlist2xschem.virtuoso_export` ports **actual xschem drawings** — coordinates,
orientations, wires, symbol graphics — to Cadence Virtuoso cellviews **and back**. No netlist
in the loop, no placement synthesis: the `.sch`/`.sym` files already carry the geometry; the
tool transforms and replays it. The artifact is a deterministic, self-contained SKILL `.il`
file, so the whole pipeline runs and golden-tests offline; only the optional load step talks
to Cadence, through `virtuoso-bridge-lite` (a lazy import — parsing/emitting never needs it).

**Why a subpackage and not its own workspace package** (plan D3, locked): the pipeline is
built on this package's xschem I/O (`sch_parser`, `sym_library`, `geometry`), and the
workspace rule is *peer leaf tools never import each other* — a standalone `xvport` peer
would violate it on day one. Heavier dependencies stay lazy/optional (`virtuoso_bridge` in
the run/reverse paths; `spicexplorer-circuitgraph` only inside the netcheck oracle, via the
`[e2e]` extra — the one sanctioned exception). If xschem I/O is ever promoted to core,
extraction becomes a mechanical refactor.

```bash
# offline: parse -> geometric net extraction -> device map -> out.il
xvport sch2cv design.sch --lib MYLIB -o out.il
# load + verify against a live CIW daemon (local mode; or bridge env resolution without --port)
xvport sch2cv design.sch --lib MYLIB --run --verify --port 65192
# port a symbol drawing (pins + body graphics + labels + termOrder)
xvport sym2cv chopper-diff.sym --lib MYLIB --run --verify --port 65192
# hierarchical: port every unmapped .sym dependency (and its .sch) depth-first, then the top
# (--mode — default `wires` — applies to every build the call makes, dependencies included)
xvport sch2cv ccia_top.sch --lib MYLIB --with-symbols --run --verify --port 65192
# print the built-in device map YAML (edit + pass back with --map)
xvport dump-map > mymap.yaml
# REVERSE: cellview -> xschem (.sch with wires/labels/pins/instances; .sym with shapes).
# --verify xschem-netlists the emitted .sch and proves circuitgraph graph equivalence
# against Virtuoso's own netlist of the cellview.
xvport cv2sch MYLIB mycell --port 65192 -o mycell.sch --verify
# ...and every user cell under it (<sub>.sym + <sub>.sch beside the output); kit masters
# map back through the table and are never dumped
xvport cv2sch MYLIB mycell --port 65192 -o rev/mycell.sch --with-symbols
xvport cv2sym MYLIB mycell --port 65192 -o mycell.sym --verify
```

Key pieces (all live-verified on IC23.1 against a licensed kit, 2026-07-16):

- **Orient table** (`xform.py`): xschem `(rot, flip)` → OpenAccess orient, `R270^rot ∘ MY^flip`;
  the Cadence side pinned by a placed-instance spike, the xschem side by a corpus regression
  (`test_geometry.py`). Default scale `0.0125` maps xschem's 5-unit grid exactly onto the
  0.0625 Cadence snap.
- **Geometric net extraction** (`netex.py`): union-find over wire segments (endpoints +
  T-junctions) + labels/ports folded in by name + device pins bound via transformed `.sym`
  pin boxes. The corpus fixtures assert electrically-correct partitions.
- **Two connectivity modes** (`--mode`): `wires` (**default**) — the drawing's wires
  verbatim (pre-split at junctions), one label per connected island, and geometric pin
  patching (a no-op for ported local symbols, whose pin geometry is a scaled copy);
  `labels` — net-label stubs at every terminal, immune to xschem↔kit pin-geometry
  mismatch, but it draws **no wiring**. A `labels` cellview netlists correctly and looks
  unwired to the person who opens it, and no gate here can tell the two apart (netcheck,
  the read-back and a post-port re-simulation all pass), so the port defaults to `wires`
  and `labels` warns once per run (#267). The mode applies to every cellview a call
  builds, `--with-symbols` dependencies included. In `labels` mode an instance whose stubs
  would still run along one line after the #236 fan-out — drain, source and bulk on one
  straight run — is REFUSED, naming the instance and its terminals, unless
  `--allow-collinear-labels` is passed.
- **CDF params fire their callbacks** (`xvSetParams` in the emitted `.il`) — never bare
  `dbReplaceProp`; on a per-finger-CDF kit, setting `w` correctly derives `wf` (the classic width trap).
  The multiplier maps to `simM` (the netlister's `m←simM`; CDF `m` is itself
  callback-derived, so writing it is a silent no-op). Every mapped parameter is then stored
  **explicitly**: `cdfUpdateInstParam` keeps only what differs from the master's default, so a
  device sized at its default carried no property at all and a lost sizing read back identical
  to a correct port (#241) — the emitter fills in what the setter left absent (never
  overwriting a callback-derived value) and each cell reports `N params explicit[, M omitted
  (reason: …)]`.
- **Device map** (`devmap.py`, YAML): xschem symref ⇄ Cadence master + terminal aliases +
  param names; ships IHP-MOS→a placeholder kit lib (topology port — sizing is not kit-translated) and
  generic→analogLib rules; `kit_libs` is the reverse-direction NDA denylist. A rule's
  `per_finger: {total: w, fingers: ng}` divides a TOTAL-width attribute for a per-finger
  CDF `w` (IHP xschem `w` is total; a per-finger kit has `wf = w × fingers`) — symbolic values that
  can't divide drop the width with a warning instead of netlisting at `ng×` size.
- **A testbench's ground and its sources** (`globals:` + `stimulus:` in the map,
  `stimulus.py` for the grammar): SPICE `0` becomes the Cadence global `gnd!` (the only
  defaulted global — a rail is a design choice), and a source's one `value="dc 0.2 ac 0"`
  is split across the CDF fields that hold it, with the stimulus kind free to select its
  own master (`vpulse` is not a `vdc`). The grammar yields canonical field names; every CDF
  spelling stays in the map. An unreadable stimulus, a parsed field the map routes nowhere,
  and a non-numeric value all **fail the port** (`--allow-symbolic` opts into the last) —
  each was previously a warning beside a successful port that had changed the circuit. A CDF
  name the master has not got fails the **load** the same way (`#214`): it used to be a CIW
  `printf` nothing client-side read, which is how a map spelling the CDF for another kit
  ported a whole bench of zero-amplitude sources and still reported success.
- `--verify` reads the built cellview back (`read_schematic`/`read_symbol_ports`) and diffs
  instances, terminal→net bindings, ports, and symbol terminals against the emitter's
  expectation tables — the machine-checkable success signal.
- **End-to-end checks** (`endcheck.py`) run by default after `--run` and are *independent
  oracles* (neither reuses xvport's own net extractor):
  - **netcheck** (`--no-netcheck` to disable): netlists the SOURCE with headless `xschem -n`
    and every built schematic with Virtuoso's own netlister (spectre dialect, via the
    bridge), then proves **circuitgraph graph equivalence** — labeled bipartite-graph
    isomorphism over device type + MOS polarity + pin wiring, names/sizing ignored, supply
    rails anchored. Requires the `[e2e]` extra (spicexplorer-circuitgraph — the one
    sanctioned lazy cross-leaf import) + xschem on PATH; SKIPs with the reason otherwise.
    `--strict-netcheck` adds the model name to each device's label and compares
    `w`/`l`/`m`/`nf` by name across the isomorphism (eng-normalized, 0.1 %) — for a
    **same-kit** port, where a neighbouring threshold flavour or a sizing error is otherwise
    invisible; a cross-kit topology port changes both on purpose and must not ask for it.
  - **simcheck** (`--no-simcheck` to disable): wraps the top cellview's exported netlist in
    a smoke deck — `--sim-models`/`--sim-section` (or `XVPORT_SIM_MODELS`/
    `XVPORT_SIM_SECTION`) supply the user's model include; every interface net is tied
    to ground through 1 GΩ — and solves a DC operating point through Spectre. `--sim-env`
    pins the bridge profile (its `.env` discovery can silently pick a remote-SSH one);
    `--sim-param name=val` (repeatable) gives values to a drawing's symbolic placeholders.
    The exported netlist's own kit-path include lines are STRIPPED (`extract_design_section`,
    NDA posture) — the user-supplied include is the single model source.

- **Reverse porting** (`reverse.py`, `cv2sch`/`cv2sym`): the two readback gaps (schematic
  wire geometry, symbol drawing shapes) are filled by SKILL dumps in this package via the
  bridge's `execute_skill`; every forward transform is inverted (8-orient table, scale +
  y-negation, `simM`→`m`, per-finger `w × fingers` → total). **The `kit_libs` NDA denylist
  is ENFORCED**: dumping a kit-library cellview raises before any client call — kit-master
  *instances* map back through the table (each rule's `symref`). Round-trip proven live:
  Cadence → `.sch` → Cadence again re-ports graph-equivalent (the default `--mode wires`
  is the natural re-port mode for the wire-accurate reverse output). Symbol arcs are ported
  as xschem `A` records (offline-tested; not yet run against a live daemon), and any other
  device-layer shape type the dump does not read is named in a warning. `cv2sch --with-symbols`
  (`cv2sch_hierarchy`) walks the user cells under a schematic depth-first, writing each
  one's `.sym` + `.sch` beside the top; a kit master is never dumped.
- `--prefix xv_` renames locally-created cells (collision escape hatch vs kit cell names);
  sanitized name collisions get deterministic suffixes + warnings.

## Rendering notes (xschem)

- xschem lives in the EDA Docker image (`spicexplorer-spice-base:local`); it is **not** on the macOS
  host. `render()` degrades gracefully when it's absent.
- **SVG** is exported headlessly (xschem's cairo backend). **PNG** is produced by rasterizing that SVG
  — xschem's native `--png` needs an X server, which the headless image lacks. Three rasterizers are
  tried, in order of fidelity, and `RenderResult.rasterizer` names the one that ran:
  1. [`cairosvg`](https://cairosvg.org) (`pip install 'spicexplorer-netlist2xschem[render]'`) — xschem's
     own rendering library, and the faithful path;
  2. `rsvg-convert`, if it is on `PATH`;
  3. ImageMagick (`magick`/`convert`) as a last resort. Its **built-in (MSVG) renderer loses drawing**,
     so taking this leg logs a loud warning (issue #225) — the `.svg` beside the PNG is always right.

  With none of the three installed, `render(fmt="png")` returns the SVG with a note rather than a
  half-drawn raster.
- **The exported `.svg` is post-processed in place** before anything reads it, so a caller that
  rasterizes the SVG itself gets a faithful picture:
  - `fit_viewport()` widens the viewport to the geometry the sheet really uses, **including the drawn
    width of text at the edges** — a port name is placed with `transform="translate(..)"` and would
    otherwise be clipped out of the export (issues #159, #224);
  - `stroke_safe_svg()` copies each element's CSS-class declarations onto it as `stroke` /
    `stroke-width` / `fill` attributes and gives a zero-area stroked path a fill equal to its stroke.
    Both are no-ops for a conformant renderer (the `<style>` block stays and keeps winning the
    cascade; filling a zero-area path paints nothing) — verified byte-identical through `cairosvg` —
    and they are what stops a `fill:none` wire vanishing under MSVG (issue #225).

  Consequence for a repo that **commits** a rendered sheet: the `.svg` bytes differ from what earlier
  releases wrote, so expect a one-time diff on the next regeneration. The drawing is unchanged.
- **The sheet's own text is checked, and repaired** (issue #239). xschem sizes the export from the
  bounding box of the DRAWN objects (padded to the export's aspect) and writes nothing outside it,
  so a `T` record above the topmost wire — a title — is **absent from the SVG, not clipped in it**.
  After the export every judgeable `T` record is looked for in the file; if any is missing, the
  sheet is exported once more from a *render-time copy* carrying an invisible layer-0 extent line
  across the text's box (the committed `.sch` is never modified and the record is never moved).
  Whatever is still missing lands in `RenderResult.texts_dropped` and in a logged warning;
  `RenderResult.text_elements` reports the `<text>` count for the record. A sheet whose text
  already renders is exported once and byte-identically to before — the decision is xschem's own
  export, not a re-implementation of its bbox rule.
- Symbol resolution is seeded via a generated `xschemrc` (`--rcfile`), so it works regardless of the
  container's `HOME`.
- That `xschemrc` is **checkout-independent** (issue #248): the output directory's own library entry
  is written as `.` (an entry nested inside it, relative to it), and only entries *outside* the
  output directory stay absolute. A design that commits the file beside its sheets therefore gets
  byte-identical bytes from every clone, and a re-netlist run *from* the output directory still
  resolves the design's own symbols. The `** sch_path:` comment in a re-netlisted `.spice` is
  xschem's own stamp of the absolute sheet path it was handed — not written by this package.

## Consumers

- **REST API:** `POST /api/xschem/from-netlist` (in `spicexplorer-api`) wraps this tool — it takes a
  netlist path or raw text, returns the `.sch` content (plus an optional rendered image path), and
  persists the `.sch` under `work_root()` so `GET /api/xschem/file` serves it to the viewer. In the UI,
  use the **“From netlist”** button in the Schematic tab.
- **analog-db raw export:** `analog-db export-raw` calls `to_sch(from_string(...))` to emit a
  deterministic `raw/<class>/<circuit>/<circuit>.sch` per circuit (drift-guarded alongside the decks);
  `analog-db export-raw --svg` renders those `.sch` to `.svg` via `render()` in the EDA container.
  The dependency direction is analog-db → this leaf tool (never the reverse).

## Tests

```bash
uv run pytest packages/spicexplorer-netlist2xschem/tests          # host: pure-Python (no xschem)
uv run pytest packages/spicexplorer-netlist2xschem/tests -m slow  # in the EDA container: render + round-trip
```

The `slow` tests render via xschem and assert the round-trip (generated `.sch` → `xschem -n -s` →
reparse) reproduces the original device set and connectivity. They auto-skip when xschem is absent.
The *hierarchy* round-trip gates on a structural `circuitgraph.netlists_equivalent` (labeled-graph
isomorphism); this *flat* unit round-trip compares device/net **names** (sound here because xschem
preserves them). The structural-isomorphism gate over the **whole** generated catalogue lives in
analog-db (`tests/test_slow_sch_roundtrip.py`, every non-hierarchical `.sch` under `raw/` via `compare_netlists`); see the meta-repo
`doc/archive/todo_block_annotation.md` (P11, done).
